# 骑砍 1.011（Mount & Blade 1.011）修改工具箱 · 中文说明

面向 **WD - Minuet (v0.12 Full)** 模组开发/调试的逆向工程工具，理论上也适用于其它基于
Native 的 1.011 模组（工具不写死模组内容，模块目录可自动探测或手动指定）。

> ⚠️ 实验性工具：所有修改都可能破坏存档或模组。**动手前请先备份 `.sav` 存档和模组目录。**

---

## 一、两套工具，别混淆

| 工具 | 编辑对象 | 生效时机 | 文件 |
|---|---|---|---|
| **兵种/物品查看器** | 抽象模板 `troops.txt` / `item_kinds1.txt` / `party_templates.txt` | 物品/部队模板改动**全局随时生效**（影响所有存档）；兵种改动**开新档生效** | `兵种物品查看器_v2.py`（中文）<br>`troop_item_viewer_v2_EN.py`（英文） |
| **存档修改器** | 二进制存档实例 `.sav` | 改动只影响该存档，保存后重新载入即生效 | `mb_editor_gui.py`（中文）<br>`mb_editor_gui_EN.py`（英文） |

两者文件不同、数据不同、生效规则不同，互不引用。

---

## 二、运行要求

- Python 3.8+，**必须带 tkinter**（Windows 官方安装包 / Anaconda 均自带；若报
  `ModuleNotFoundError: No module named 'tkinter'`，请换一个带 tkinter 的 Python）。
- 无需安装任何第三方库。

## 三、启动方式

1. **双击 `run_all.py`** → 弹出选择窗口，点按钮启动（推荐，非技术用户友好）；
2. 或命令行：`python 兵种物品查看器_v2.py` / `python mb_editor_gui.py` 等；
3. 或：`python run_all.py 1`（1=中文查看器，2=英文查看器，3=中文存档修改器，4=英文存档修改器）。

## 四、模组目录怎么找的（可移植）

工具不再依赖本机硬编码路径，解析优先级：

1. 环境变量 `MB_MODULE_DIR`（直接指定模块目录）
2. `--module <目录>` 命令行参数（存档修改器支持）
3. 上次成功载入的模块（记在同目录 `mb_module_path.json`）
4. 自动探测：环境变量 `MB_MODULES_DIR` → 注册表/Steam 库中的 `MountBlade/Modules`
   → 常见安装路径（`E:/D:/C:\Program Files\Game\Mount&Blade\Modules` 等）
5. 以上都没有 → 弹出目录选择框，选一次后自动记住

**拷给别人用时**：把整个文件夹拷过去即可，首次运行会弹框让对方选一次自己的模组目录，之后自动记住。
（可选：把 `mb_module_path.json` 删掉再分发，里面是你本机的路径记录。）

## 五、功能一览

### 兵种 / 物品查看器（抽象模板）
- 兵种：属性、熟练度、技能、背包 64 槽、装备 10 槽、**标志位 tf\_\* 勾选式编辑**、
  **升级链显示**、阵营投靠、与存档实例的逐兵种对照
- 物品：完整属性解码（价格 / 重量 / 丰裕度 / 防御 / 武器 / 马匹 / 盾牌 / 弹药 / 投射）、
  属性**可编辑**（价格、重量、丰裕度、后续数值）
- 部队模板 `party_templates.txt`：兵种栈查看与编辑
- 保存写回时自动生成 `原名.<时间戳>.bak` 备份

### 存档修改器（.sav 实例）
- 兵种：属性 / 熟练 / 技能 / 等级 / 经验 / 背包 / 装备 / 简介
- **标志位 tf\_\* 勾选式编辑**（与十六进制输入框双向同步）
- 阵营：查看与改归属、**执行跳槽**（同时改兵种阵营和其部队归属）
- **提拔英雄为领主**（可选封地）
- 部队：查看堆叠、改部队归属阵营（城池/城堡/村庄可转移管辖）
- 保存时生成 `.sav.bak_<时间戳>` 备份

## 六、已知限制（务必阅读）

1. **写权限**：模组若装在 `Program Files` 下，保存 `troops.txt` / `item_kinds1.txt`
   需要**管理员权限**（受保护目录，否则会静默失败）。可把模组移到普通目录，或右键管理员运行。
2. **改模板是全局的**：`troops.txt` / `item_kinds1.txt` 的改动影响**所有存档**（物品即时，兵种开新档）。
3. **未实机全量验证**：解析与写回已做往返测试（889 物品逐字节一致、794 兵种往返一致），
   但**游戏运行时是否完整采纳**这些写入值仍需实测，尤其是：
   - 「提拔为领主」未写兵种 slot10(led_party) 与封地 slot7(town_lord)，靠 party `stack[0]` 链接；
   - party 记录尾部约 4632 字节的槽区尚未解码 → 封地"属于哪位领主"无法精确改写。
4. **英雄识别依赖中文简介**：存档中英雄的中文简介用于匹配，英文版仅在显示层转英文，不影响匹配。
5. 未实例化（占位）的英雄、UI 菜单占位兵种会被标记为"未生成"并拒绝编辑，属预期保护行为。
